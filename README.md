# Ranobe Downloader

Python CLI для скачивания текстовых глав RanobeLib в EPUB 3.

> Alpha. Используйте только для произведений, на скачивание которых у вас есть право. Соблюдайте ограничения API.

## Требования

- Python 3.10+
- Доступ к RanobeLib API
- Для хранения токена: работающий системный keyring

## Установка

Из корня проекта:

```bash
python -m venv venv
source venv/bin/activate
python -m pip install -e .
ranobe --help
```

Без установки доступен запуск `python main.py`.

## Авторизация

Если API требует токен, сначала выполните:

```bash
ranobe login
ranobe status
```

Токен вводится скрыто и сохраняется через системный keyring. Для удаления: `ranobe logout`. Не передавайте токен через аргументы командной строки.

## Скачивание

```bash
ranobe download "55754--cuttlefish-that-loves-diving" \
  --branch 27521 \
  --resume \
  --delay 0.5 \
  --output output/book.epub
```

Параметры:
- `--branch ID` — явный выбор переводчика, без интерактивного меню.
- `--non-interactive` — запрещает запрос ввода; при нескольких переводах требуется `--branch`.
- `--resume` — использовать ранее сохранённые главы из кеша.
- `--cache-dir PATH` — папка кеша, по умолчанию `output/.cache`.
- `--delay SECONDS` — задержка между запросами глав (по умолчанию 1).
- `--retries N` — максимальное число попыток (по умолчанию 5).
- `--limit N` — скачать только первые N глав для проверки.
- `--output PATH` — путь результирующего EPUB.
- `--verbose` — подробный лог загрузки каждого изображения; без флага вывод компактный.
- `--image-mode original|optimized` — оригинальные файлы (по умолчанию) или оптимизация PNG.
- `--image-quality N` — качество JPEG (1–100, по умолчанию 85), только для `optimized`.
- `--image-max-width N` — ограничение ширины конвертируемых PNG (по умолчанию 1600).

При HTTP 429 загрузчик учитывает `Retry-After` и пробует запрос ещё раз. Уже сохранённые главы доступны для последующего запуска с `--resume`.

EPUB содержит оглавление и метаданные. Обложка загружается отдельно и, если недоступна, пропускается. Изображения структурированных ProseMirror-глав поддерживаются (см. ниже).

```bash
python -m unittest discover -s tests -v
```

## Структура

- `core/` — модели, логика скачивания, чекпоинты, повторные попытки.
- `providers/libsocial/` — интеграция с API.
- `exporters/` — создание EPUB.
- `interfaces/cli/` и `main.py` — командный интерфейс.

Проект находится в разработке, обратная совместимость CLI пока не гарантируется.


## Выпуск версии (maintainers)

Текущая версия указана в `pyproject.toml`; CLI показывает её через `ranobe --version`.

1. Убедитесь, что изменения проверены и включены в целевую стабильную ветку.
2. Установите новую версию в `pyproject.toml` и закоммитьте изменение.
3. Создайте и отправьте тег, соответствующий версии по PEP 440:

```bash
# Для version = "0.1.0a1"
git tag v0.1.0a1
git push origin v0.1.0a1
```

Workflow `.github/workflows/release.yml` проверяет соответствие тега версии, запускает тесты, собирает wheel и sdist, проверяет wheel в отдельном venv и публикует файлы в **GitHub Releases** как prerelease.

Тег должен указывать на проверенный релизный коммит. Публикация в PyPI **не выполняется**.

## Изображения внутри глав

Для структурированных ProseMirror-глав `image` связывается с `attachments` по UUID.
JPEG, PNG, GIF и WebP скачиваются с доверенных источников и встраиваются в EPUB.
Файлы сохраняются в `--cache-dir`, поэтому `--resume` повторно использует изображения.
Если вложение отсутствует или недоступно, скачивание завершается с ошибкой вместо незаметной потери иллюстрации.

```bash
ranobe download "246638--heonteodeul-i-jibchaghaneun-jeongsinsangdamsaga-doeeossda" --branch 27690 --resume --limit 66 --output output/images-test.epub
```

Обратите внимание: `--limit 66` скачивает первые 66 глав, а не только главу №65.
HTML-теги `<img>` в старых строковых главах поддерживаются для проверенных путей `/uploads/ranobe/...` на RanobeLib и доверенных CDN. Такие изображения загружаются и кешируются тем же движком, что и изображения ProseMirror. Если URL нельзя безопасно разрешить, загрузка останавливается с ошибкой вместо пропуска иллюстрации.
Аудит проверяет структуру вложений, но не их доступность по сети.

### Оптимизация изображений EPUB

По умолчанию используется `--image-mode original`: файлы встраиваются без изменений.
Режим `optimized` требует Pillow:

```bash
pip install -e '.[images]'
ranobe download '246638--heonteodeul-i-jibchaghaneun-jeongsinsangdamsaga-doeeossda' --branch 27690 --limit 66 --resume --image-mode optimized --image-quality 85 --image-max-width 1600 --output output/images-optimized.epub
```

При оптимизации PNG без существенной прозрачности (минимальный alpha ≥ 250 из 255) накладываются на белый фон и кодируются в JPEG, **только если JPEG меньше исходного PNG**. Широкие PNG перед кодированием уменьшаются по ширине. PNG с существенной прозрачностью (alpha < 250), исходные JPEG, WebP и GIF остаются неизменными. Это сжатие с потерями; при необходимости сохранить качество используйте `original`. Оригиналы в кеше не изменяются; переключение режимов с `--resume` не требует повторной загрузки медиафайлов.

## Итоговая статистика

После успешной сборки команда `ranobe download` показывает число глав (в том числе взятых из кеша), число изображений, исходный размер изображений, размер изображений внутри EPUB, экономию в МиБ и процентах и итоговый размер файла EPUB. Во время загрузки показываются номер главы и процент выполнения; подробные сообщения о скачивании каждого изображения доступны через `--verbose`.

Экономия рассчитывается по суммарным размерам изображений **до и после оптимизации**, а не по двум EPUB-файлам. Поэтому процент может отличаться от отношения размеров EPUB в режимах `original` и `optimized`.

## Выбор переводчика

При нескольких ветках перевода команда `ranobe download` в интерактивном терминале показывает названия команд (если API их предоставляет), ID и количество глав. Можно выбрать номер из списка или отменить выбор через `q`. Единственная ветка выбирается автоматически. В CI, скриптах или при `--non-interactive` выбора нет — передайте `--branch ID`.

Движок не зависит от CLI: `BookDownloader.prepare(reference)` получает метаданные, индекс глав и `translations`; `BookDownloader.download(plan, output, branch_id=...)` использует подготовленный `DownloadPlan` без повторной загрузки метаданных. Старый вызов `download(reference, ...)` также работает и не запрашивает ввод: при неоднозначном переводе выдаёт `ValueError`. Таким образом GUI или Web API смогут самостоятельно показывать список переводчиков.

## Аудит совместимости

`ranobe audit REFERENCE --branch ID --mode metadata` проверяет индекс и метаданные, не загружая содержимое глав. `--mode sample --sample 30` проверяет выборку из 30 глав; `--mode full` проверяет **все главы выбранного перевода**, без создания EPUB и скачивания изображений. Для нескольких переводов указывайте `--branch`, иначе результат будет `INCONCLUSIVE`.

CLI подсвечивает статусы в интерактивном терминале: зелёный `COMPATIBLE`, красный `INCOMPATIBLE`/`ERROR`, жёлтый `INCONCLUSIVE`, голубой `NOT_TESTED`. `--no-color` отключает цвета; учитывается `NO_COLOR`. Любой статус кроме `COMPATIBLE` возвращает ненулевой код завершения. JSON-отчёт не содержит ANSI-кодов. Проверка ссылок изображений локальная: аудит не подтверждает их сетевую доступность.

### Длинные проверки и продолжение

Во время аудита CLI выводит прогресс, число успешных/ошибочных/непроверенных глав, прошедшее время и примерное ETA. Для периодического сохранения состояния используйте `--json PATH` (по умолчанию каждые 10 глав); запись атомарная, через временный файл. При прерывании повторите ту же команду с `--resume`: ранее завершённые главы повторно не запрашиваются. Обязательное условие — та же книга, ветка, режим и неизменный список глав; отчёты старого формата без `completed_chapter_ids` не подходят для продолжения.

```bash
ranobe audit '14841--beginning-after-the-end-novel' --branch 9824 --mode full --delay 2 --retries 5 --json output/audit-14841.json --save-every 10
# После прерывания:
ranobe audit '14841--beginning-after-the-end-novel' --branch 9824 --mode full --delay 2 --retries 5 --json output/audit-14841.json --resume
```

Чтобы исключить столкновение отчётов разных книг, сохраняйте их в отдельные JSON-файлы. Для неопределённых сетевых ошибок итоговый статус `INCONCLUSIVE`, для проблем совместимости — `INCOMPATIBLE`.

### Проверка всех переводов

`ranobe audit '14841--beginning-after-the-end-novel' --all-branches --mode sample --sample 30 --json output/audit-all-branches.json` проверяет каждый найденный перевод отдельно. Метаданные и индекс загружаются один раз; в JSON каждый перевод хранится отдельным элементом с `selected_branch`. Можно добавить `--check-images`, `--resume` и `--mode full`. Флаги `--branch` и `--all-branches` взаимоисключающие.

### Отчёты аудита

По умолчанию результаты автоматически сохраняются отдельно для каждого перевода в папку `output/audit/` с именем `<slug_url>_<branch_id>.json` (или `_default.json` для книг без перевода). Путь можно изменить через `--output-dir DIR`. Пример: `ranobe audit '14841--beginning-after-the-end-novel' --all-branches --sample 30`. `--resume` автоматически читает эти файлы. Необязательный `--json PATH` по-прежнему создаёт дополнительный объединённый JSON для совместимости со старыми сценариями.
