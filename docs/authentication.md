# Авторизация RanobeLib

[Все руководства](README.md)

Токен нужен, когда RanobeLib требует вход для доступа к произведению. Это секрет, который даёт доступ от имени вашей учётной записи. Он не открывает главы, на которые у аккаунта нет прав.

Проект принимает существующий **Bearer-токен**. Встроенной формы входа по логину/паролю и автоматического обновления токена нет. Если токена нет, сначала попробуйте публичное произведение без авторизации. Не используйте токены других людей.

## Desktop и CLI

В приложении: **Настройки → Токен → Войти**. В CLI:

```bash
ranobe login
ranobe status
ranobe logout
```

`login` запрашивает токен скрытым вводом, проверяет его и сохраняет в системном keyring. Допускается токен с префиксом `Bearer `. Desktop и CLI используют одну запись хранилища. Выход удаляет сохранённый токен; это не отзыв токена на стороне RanobeLib.

Если хранилище недоступно или заблокировано, вход с сохранением может завершиться ошибкой. Не заменяйте keyring записью токена в репозиторий. После истечения срока токена потребуется ввести новый.

## Python, HTTP и Telegram

| Интерфейс | Способ передачи |
| --- | --- |
| Python API | Явно через `Downloader(token=...)`; библиотека сама не читает keyring |
| Telegram | Переменная окружения `RANOBE_TOKEN` процесса бота |
| HTTP API / Web UI | В стандартном сервере нет формы входа RanobeLib; для интеграции задайте `downloader_factory` при создании приложения |

Авторизация RanobeLib и защита HTTP-сервера — разные вещи. Передача токена провайдеру не ограничивает доступ клиентов к вашему HTTP API.

Не публикуйте токен в issue, скриншоте, логе или примере кода. При утечке отзовите его через доступные механизмы сервиса и получите новый.
