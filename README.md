# Ranobe Downloader

Python CLI для скачивания текстовых глав RanobeLib в EPUB 3.

> Alpha. Используйте только для произведений, на скачивание которых у вас есть право. Соблюдайте ограничения API.

## Требования

- Python 3.10+
- Доступ к RanobeLib API
- Для хранения токена: работающий системный keyring

## Установка

Из корня проекта:

```bash
python -m venv venv
source venv/bin/activate
python -m pip install -e .
ranobe --help
```

Без установки доступен запуск `python main.py`.

## Авторизация

Если API требует токен, сначала выполните:

```bash
ranobe login
ranobe status
```

Токен вводится скрыто и сохраняется через системный keyring. Для удаления: `ranobe logout`. Не передавайте токен через аргументы командной строки.

## Скачивание

```bash
ranobe download "55754--cuttlefish-that-loves-diving" \
  --branch 27521 \
  --resume \
  --delay 0.5 \
  --output output/book.epub
```

Параметры:
- `--branch ID` — ветка перевода; при нескольких вариантах обязательна.
- `--resume` — использовать ранее сохранённые главы из кеша.
- `--cache-dir PATH` — папка кеша, по умолчанию `output/.cache`.
- `--delay SECONDS` — задержка между запросами глав (по умолчанию 1).
- `--retries N` — максимальное число попыток (по умолчанию 5).
- `--limit N` — скачать только первые N глав для проверки.
- `--output PATH` — путь результирующего EPUB.

При HTTP 429 загрузчик учитывает `Retry-After` и пробует запрос ещё раз. Уже сохранённые главы доступны для последующего запуска с `--resume`.

EPUB содержит оглавление и метаданные. Обложка загружается отдельно и, если недоступна, пропускается. Изображения внутри глав пока не поддерживаются.

## Структура

- `core/` — модели, логика скачивания, чекпоинты, повторные попытки.
- `providers/libsocial/` — интеграция с API.
- `exporters/` — создание EPUB.
- `interfaces/cli/` и `main.py` — командный интерфейс.

Проект находится в разработке, обратная совместимость CLI пока не гарантируется.


## Выпуск версии (maintainers)

Текущая версия указана в `pyproject.toml`; CLI показывает её через `ranobe --version`.

1. Убедитесь, что изменения проверены и включены в целевую стабильную ветку.
2. Установите новую версию в `pyproject.toml` и закоммитьте изменение.
3. Создайте и отправьте тег, соответствующий версии по PEP 440:

```bash
# Для version = "0.1.0a1"
git tag v0.1.0a1
git push origin v0.1.0a1
```

Workflow `.github/workflows/release.yml` проверяет соответствие тега версии, запускает тесты, собирает wheel и sdist, проверяет wheel в отдельном venv и публикует файлы в **GitHub Releases** как prerelease.

Тег должен указывать на проверенный релизный коммит. Публикация в PyPI **не выполняется**.

## Изображения внутри глав

Для структурированных ProseMirror-глав `image` связывается с `attachments` по UUID.
JPEG, PNG, GIF и WebP скачиваются с доверенных источников и встраиваются в EPUB.
Файлы сохраняются в `--cache-dir`, поэтому `--resume` повторно использует изображения.
Если вложение отсутствует или недоступно, скачивание завершается с ошибкой вместо незаметной потери иллюстрации.

```bash
ranobe download "246638--heonteodeul-i-jibchaghaneun-jeongsinsangdamsaga-doeeossda" --branch 27690 --resume --limit 66 --output output/images-test.epub
```

Обратите внимание: `--limit 66` скачивает первые 66 глав, а не только главу №65.
HTML-теги `<img>` в старых строковых главах пока не поддержаны; здесь реализованы изображения из JSON/ProseMirror.
Аудит проверяет структуру вложений, но не их доступность по сети.

### Оптимизация изображений EPUB

По умолчанию используется `--image-mode original`: файлы встраиваются без изменений.
Режим `optimized` требует Pillow:

```bash
pip install -e '.[images]'
ranobe download '246638--heonteodeul-i-jibchaghaneun-jeongsinsangdamsaga-doeeossda' --branch 27690 --limit 66 --resume --image-mode optimized --image-quality 85 --image-max-width 1600 --output output/images-optimized.epub
```

При оптимизации непрозрачные PNG кодируются в JPEG, если он меньше исходника; широкие PNG уменьшаются по ширине. Изображения с прозрачностью, JPEG, WebP и GIF остаются неизменными. Оригиналы в кеше не изменяются; переключение режимов с `--resume` не требует повторной загрузки медиафайлов.
