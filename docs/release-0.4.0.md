# Выпуск 0.4.0

1. Дождитесь успешных Python CI, Web UI CI и PySide6 desktop для подготовленного коммита develop. Скачайте AppImage из CI artifacts и проверьте загрузку книги, очередь, отмену, историю и трей. Для Windows/macOS проверьте соответствующие сборки на этих ОС.
2. Слейте develop в main и отправьте main. Дождитесь успешного CI на main.
3. Проверьте чистое рабочее дерево и версию 0.4.0 в pyproject.toml. Создайте аннотированный тег v0.4.0 на проверенном коммите main и отправьте тег.
4. Release проверяет версию тега, запускает тесты, собирает Python-пакеты и Web UI, создаёт GitHub Release. Затем в том же запуске вызывается PySide6 desktop: сборки трёх ОС прикладываются к релизу.
5. Проверьте успешное завершение всех jobs и наличие шести файлов: wheel, sdist, Web UI tar.gz, EXE, DMG и AppImage.

Если desktop-сборка упала, релиз уже может содержать Python и Web UI. Исправление исходников требует нового тега версии; повторный запуск применяет исходный коммит. Для временной инфраструктурной ошибки можно повторить упавшие jobs.

Не перемещайте уже опубликованные теги. API остаются экспериментальными.
