# Участие в разработке

Принимаются исправления, документация и предложения. Чтобы сообщить об ошибке, достаточно issue с версией, ОС и шагами воспроизведения.

## Предложить изменение

1. Проверьте существующие issues и PR. Крупное изменение сначала обсудите в issue.
2. Создайте fork и рабочую ветку от актуального `develop`. Участники с правом записи могут использовать ветку основного репозитория.
3. Используйте имена `feature/...`, `fix/...` или `docs/...`.
4. Откройте PR в `develop`: опишите проблему, результат и проверки.

Один PR — одна связанная задача. Слияние выполняется после CI и проверки сопровождающим. Релизные PR идут из `develop` в `main`; прямой push в эти ветки не используется.

## Среда разработки

Выполните [установку из исходников](docs/installation.md):

```bash
python -m pip install -e '.[desktop,http,telegram,images]'
python -m unittest discover -s tests -v
```

Для Linux без дисплея задайте `QT_QPA_PLATFORM=offscreen`. В `web` выполните `npm install` и `npm run build`.

Для исправлений добавляйте тесты воспроизведения и существенного поведения. Используйте детерминированные фиктивные данные вместо реальных запросов, когда это возможно.

## Структура

| Каталог | Назначение |
| --- | --- |
| `core/` | Главы, кеш, загрузка и нормализация |
| `providers/` | Источники данных |
| `exporters/` | EPUB, TXT, HTML |
| `ranobe_downloader/` | Python API |
| `interfaces/` | CLI, PySide6, HTTP, Telegram |
| `web/` | Фронтенд Vue |
| `tests/` | Автоматические проверки |
| `docs/` | Руководства |

Новые интерфейсы используют ядро, новые источники размещаются в `providers/`. При изменении публичного поведения обновляйте документацию.

Не включайте секреты, персональные данные, книги и кеш. Проверяйте также логи и скриншоты. Уязвимости: [SECURITY.md](SECURITY.md).

[Процесс релиза](docs/releasing.md) описывает публикацию. Предоставляйте только материалы, которые вправе распространять под [MIT](LICENSE). У внешних зависимостей сохраняются их условия лицензирования.
