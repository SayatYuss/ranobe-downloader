# Безопасность

## Сообщить об уязвимости

Не публикуйте токены, персональные данные и чувствительные подробности эксплуатации в публичном issue.

Если доступна кнопка **Security → Advisories → Report a vulnerability**, используйте её для приватного отчёта. Если приватного канала нет, откройте issue без технических подробностей и секретов с просьбой предоставить безопасный канал связи.

В приватном отчёте укажите версию, условия воспроизведения и влияние. Проект находится на ранней стадии; фиксированных сроков реакции и поддержки старых версий нет.

## Токены и диагностика

Desktop и CLI используют keyring. Python API принимает токен явно, Telegram — из окружения. Не включайте токены в исходники, URL, issue и скриншоты. Локальный выход не обязательно отзывает токен на стороне сервиса.

При утечке отзовите секрет и получите новый. Удаление последним коммитом не удаляет его из истории Git. История Desktop содержит локальные пути и метаданные: проверяйте диагностику перед публикацией.

## Сервер и бот

- HTTP API не имеет аутентификации клиентов, ролей и изоляции файлов. Для локального запуска используйте `127.0.0.1`.
- Внешнее размещение требует контроля доступа, HTTPS и ограничений запросов.
- Токен RanobeLib не защищает ваш HTTP-сервер от других клиентов.
- Для личного бота задайте `TELEGRAM_ALLOWED_USER_IDS`; без списка запросы доступны любому пользователю Telegram.
